Tiny LLM Lab

A language model built from scratch in ~500 lines of JavaScript, running entirely in your browser. Each section shows one core idea behind models like GPT and Claude, at toy scale.

1Tokenization (byte-pair encoding)

Models don't read letters or words; they read tokens. BPE starts with single characters and repeatedly merges the most frequent adjacent pair. Slide to see how more merges turn characters into word pieces.

Real models learn ~100k merges from terabytes of text. Here the merges are learned from the tiny corpus in the Training tab, so words it has seen compress well and unseen ones fall back to characters.
How this works, in depth

Why tokens at all?

A neural network only handles numbers, so text must first be cut into pieces that each get an integer ID. Splitting into whole words needs a gigantic vocabulary and fails on any word it hasn't seen. Splitting into single characters never fails, but sequences become very long and each character carries little meaning. Sub-word tokens are the compromise: common words become one token, rare words are assembled from several pieces, and nothing is ever "unknown".

How byte-pair encoding learns its vocabulary

  1. Split the corpus into words (a word keeps its leading space, shown as ␣) and write each word as a list of characters.
  2. Count every pair of neighbouring symbols across the whole corpus, weighted by how often each word occurs.
  3. Take the most frequent pair (it must occur at least twice) and merge it into one new symbol everywhere. Record the merge.
  4. Repeat. Each pass adds one symbol to the vocabulary; the ordered list of merges is the tokenizer.

To encode new text, start from characters and replay the recorded merges in the same order. That is exactly what the slider does: it replays only the first k merges.

What you are seeing

  • 0 merges: one token per character (the longest possible sequence, the smallest vocabulary).
  • Early merges capture frequent letter pairs and short words such as th and the.
  • Later merges join whole words including the leading space (␣cat, ␣garden). The token count drops, but the vocabulary grows.
  • The token count is what a real LLM is billed and limited by: context windows and prices are measured in tokens, not characters.

How this differs from production tokenizers

GPT-style tokenizers run BPE over raw bytes (so any Unicode text is representable), use a vocabulary of tens of thousands to a few hundred thousand tokens, and are trained once on a huge text sample before the language model itself is trained. The model never sees letters, only these IDs. That is why models can be surprisingly bad at tasks like counting the letters in a word.

Try it: type a word that is not in the corpus (for example elephant) and drag the slider. It mostly stays as single characters, because few or no learned merges apply to it. Then type the cat sat on the mat. and watch it collapse into very few tokens.

2Training a neural language model

The task is always the same: predict the next token given the previous ones. This little network embeds the last 3 words as vectors, mixes them through a hidden layer, and outputs a probability for every word in the vocabulary. Gradient descent nudges the weights to reduce cross-entropy loss on the corpus.

How this works, in depth

The one task behind every language model

Given the words so far, output a probability for every possible next word. Nothing else is trained. Grammar, facts and style are all by-products of getting better at this single prediction. Here the model sees the previous 3 words and chooses among the vocabulary of the corpus.

The network, step by step

  1. Embedding lookup. Each word ID indexes a row of a table and returns a vector of 12 numbers. The three vectors are joined into one input of 36 numbers. These vectors start random; they are parameters that get trained.
  2. Hidden layer. 48 neurons each compute a weighted sum of the input and squash it with tanh. Without this non-linearity the whole network would collapse into a single linear map and could not learn interactions between words.
  3. Output layer. One score ("logit") per vocabulary word.
  4. Softmax. Turns the scores into probabilities that are positive and sum to 1.

How learning happens

  1. Take one example from the corpus: three context words and the word that actually followed.
  2. Loss = −log p(correct word). It is 0 when the model is certain and right, and large when it gave the true word little probability.
  3. Backpropagation uses the chain rule to compute how much every weight contributed to the loss, working backwards from the output through the hidden layer to the embedding vectors.
  4. Gradient descent moves every weight a small step (the learning rate) in the direction that lowers the loss. This runs after every single example (stochastic gradient descent).
  5. One pass over all examples is an epoch. Examples are shuffled each epoch, and the learning rate slowly decays so the model settles down.

Reading the charts

  • Loss curve: the average loss per epoch. It starts near ln(vocabulary size) (pure guessing) and falls quickly, then flattens.
  • Perplexity = e^loss. Read it as "the model is as unsure as if it were picking evenly among this many words". A perplexity of 2 means roughly a coin flip between two candidates.
  • 3D map: each dot is a word's 12-number embedding, squeezed to 3 dimensions with PCA (which finds the three directions of greatest spread). Distances are only approximate, since 9 dimensions are dropped. The cosine-similarity list under the plot uses all 12 numbers and is more reliable.

Why similar words cluster

"cat" and "dog" are followed by the same kinds of words (sat, chased, slept), so gradient updates push their vectors in similar directions. Meaning emerges purely from usage. Bigger models learn the same effect at scale, which is why embeddings can capture relationships such as king − man + woman ≈ queen.

Limits of this toy

It sees only 3 words of context, has a few thousand weights, and learns from about 200 examples, so it can nearly memorise its corpus. Real LLMs use transformers that look at thousands of tokens, have billions of weights, and train on trillions of tokens. The training loop, however, is the same idea.

Try it: press Reinitialize & retrain and watch the loss restart from about 3.3. Edit the corpus (add sentences about a new animal such as the fox chased the mouse.) and see it join the animal cluster. Type different words in "Nearest words to" and watch the orange ring move.

3Attention

Transformers let every token look back at earlier tokens and decide how much each matters: softmax(Q·Kᵀ / √d). Row = the token doing the looking, column = the token being looked at. The causal mask stops tokens from seeing the future.

Simplified for illustration: a single head with Q = K = the trained embeddings (no learned projection matrices, no stacking of layers). Real models use dozens of layers with many heads each, all learned. The model trained in the Training tab uses a plain MLP instead of attention, but the embeddings you see here are its own.
How this works, in depth

The problem attention solves

To predict the next word, a token often needs information from earlier tokens: which noun does "it" refer to, which verb belongs to this subject. Attention lets every position look back over all earlier positions and pull in the ones that matter, with the amount of attention decided by the data instead of by a fixed window like the 3-word window in tab 2.

The computation

  1. Each token has a query vector ("what am I looking for?") and every token has a key vector ("what do I contain?").
  2. The score between token i and token j is the dot product of queryi and keyj. Vectors pointing the same way give a high score.
  3. Scores are divided by √d (d = vector size). Dot products grow with dimension, and without this scaling the softmax would saturate.
  4. Softmax across each row turns the scores into weights that sum to 1. Those are the numbers in the heatmap.
  5. In a real transformer the output for token i is the weighted average of the value vectors of the tokens it attends to, and that mix is passed to the next layer.

Reading the heatmap

  • Rows are the token doing the looking; columns are the tokens being looked at. Brighter blue means more weight, and each row adds up to 1.
  • Causal mask: when generating text, a token must not see the future, or training would be cheating. The masked upper triangle gets a score of −∞, so softmax gives it exactly zero. Untick the box to see full (bidirectional) attention, as used in models like BERT.
  • Sharpness multiplies the scores before the softmax. High values concentrate almost all weight on the single best match; low values spread it out.
  • Each token tends to attend most to itself and to earlier copies of the same word (such as "the"), because identical embeddings have the highest dot product.

What is simplified here

  • Real attention uses three separate learned matrices to make Q, K and V from each token. Here Q = K = the trained embeddings, and no values are mixed.
  • Real models have many heads per layer (each can learn a different relationship, such as syntax or coreference) and dozens of stacked layers, plus position information so word order matters.
  • The network you trained in tab 2 is a plain MLP without attention. This tab only borrows its embeddings to show the mechanism.
Try it: untick the causal mask and note that the grid fills in fully. Move the sharpness slider to the extremes. Type a sentence with repeated words (the dog and the dog and the cat) and see which columns light up.

4Sampling: generating text

The model outputs a probability distribution over the next token. Generation is: sample one, append it, repeat. Sampling settings decide how adventurous the output is. Click any bar to force that token.

Next-token distribution (after temperature, top-k, top-p; greyed = filtered out):
Low temperature sharpens the distribution toward the most likely token (repetitive, safe). High temperature flattens it (creative, eventually nonsense). Top-k keeps only the k likeliest tokens; top-p keeps the smallest set whose probabilities sum to p.
How this works, in depth

Generation is a loop

  1. Feed the text so far (its last 3 words here) to the network from tab 2 to get a score for every vocabulary word.
  2. Turn the scores into probabilities with softmax, reshaped by the sampling controls above.
  3. Randomly draw one word in proportion to its probability.
  4. Append it to the text and go back to step 1. A "." resets the context, just as in training.

The model never plans a sentence. Every word is a fresh draw from a distribution, and the appearance of fluent text comes from each draw being well informed by what came before. Because the draw is random, the same prompt gives different outputs each time.

The three controls

  • Temperature divides the scores before softmax. Below 1 the gap between likely and unlikely words widens (near 0 you always get the top word, which is greedy decoding: safe but repetitive and prone to loops). Above 1 the distribution flattens, so unlikely words appear more often (varied, then incoherent). At 1 you see the model's raw, unmodified beliefs.
  • Top-k keeps only the k most likely words and discards the rest. It stops rare, nonsensical words from ever being sampled, but a fixed k is blunt: sometimes 2 words are reasonable, sometimes 50.
  • Top-p (nucleus) keeps the smallest set of top words whose probabilities add up to p. It adapts automatically: few candidates when the model is confident, many when it is unsure.

After filtering, the surviving probabilities are rescaled to sum to 1, which is why kept bars show larger percentages than before. Greyed-out bars marked "cut" are excluded. Real systems usually combine all three.

Reading the bars

Each bar is one candidate next word, sorted by probability; the list shows the top 12. A very tall first bar means the model is confident (for example, finishing a common phrase). Bars of similar height mean it is genuinely torn. You can click any bar to force that word, which is a handy way to steer the text and see how the next distribution reacts.

Why this matters for real LLMs

Chat models use exactly this loop, just with a much bigger network and vocabulary. Hallucination is partly a consequence: the model always outputs some probability distribution, so a fluent-sounding token can be sampled even when the model has no real knowledge. Settings like temperature are why an assistant can be made more deterministic for code and more varied for creative writing.

Try it: set temperature to 0.05 and press Generate 20 a few times (you will see nearly identical, repetitive output). Then raise it to 2.5 and watch the text degrade. Set top-k to 1: it is equivalent to greedy decoding at any temperature. Finally, keep temperature at 1 and set top-p to 0.5 to see only the head of the distribution survive.
